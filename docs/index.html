The problem

Two good ideas that never met.

Doc-first

Write in a Google Doc and let a pipeline render it. Durable and collaborative, but authors can't see or edit the finished page.

| Hero | | title | Hello | | image | (img) |

Page-first

Edit the rendered page directly. A great gesture, but the source of truth becomes HTML instead of a Doc your team already lives in.

<h1 contenteditable> Hello </h1>

This app is the combination: the page-first editing gesture, with the doc-first source of truth.

How it works

Simplicity first.

Preview every change exactly as visitors will see it, then publish with confidence.

  1. EditChange words, images and layout right on the page. Nothing is saved yet.
  2. CommitYour changes are pushed to the Google Doc through Google's own API.
  3. RenderThe server pulls the change back out of the Doc, then re-renders the page's HTML in its final state.
  4. PublishThe finished HTML is uploaded to Cloudflare.

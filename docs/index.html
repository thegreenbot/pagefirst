The problem

Two good ideas that never met.

Doc-first (Adobe EDS)

Write in a Google Doc. A pipeline renders it. Durable and collaborative — but authors can't see or edit the finished page.

| Hero | | title | Hello | | image | (img) |

Page-first (DA.live)

Edit the rendered page directly. Great gesture — but the source of truth becomes HTML, not a Doc your team already lives in.

<h1 contenteditable> Hello </h1>

This app is the combination: the page-first editing gesture, with the doc-first source of truth.

How it works

One rule keeps it honest.

Every feature speaks one intermediate page structure. The preview DOM is never saved, and never what gets published.

  1. EditThe editor mutates the page structure in a local draft.
  2. CommitThe structure is translated into Google Docs API requests.
  3. Re-readThe server re-reads the Doc and returns the parsed page. The client discards its optimistic draft and renders that result — so editor and Doc can't drift.
  4. PublishThe last committed revision is rendered to static files and uploaded to Cloudflare.
